# ۱. واحدهای پایه در سیستم

برای اینکه سیستم ساده و قابل فهم باشد، سه واحد پایه داریم:

**قیمت مرجع بازار**

\[
P_{18g} = \text{قیمت ۱ گرم طلای ۱۸ عیار}
\]

این همان مقداری است که از API می‌گیریم (`IR_GOLD_18K`).

---

**واحد وزن در سیستم**

پلتفرم‌های مثل میلی‌گلد وزن را بر اساس **میلی** نشان می‌دهند:

\[
1000 \text{ میلی} = 1 \text{ گرم}
\]

پس:

\[
1 \text{ میلی} = 0.001 \text{ گرم}
\]

---

# ۲. تبدیل قیمت گرم به میلی

چون معاملات با میلی انجام می‌شود، اول قیمت گرم را به میلی تبدیل می‌کنیم:

\[
P_{milli} = \frac{P_{18g}}{1000}
\]

که در آن:

- \(P_{milli}\) = قیمت یک میلی طلای ۱۸ عیار

---

# ۳. قیمت طلای خام برای یک محصول

فرض کن محصولی در دیتابیس داری با:

- وزن = \(W_m\) میلی

پس ارزش طلای خالص آن می‌شود:

\[
BasePrice = P_{milli} \times W_m
\]

یا اگر بخواهیم از گرم بنویسیم:

\[
BasePrice = P_{18g} \times \frac{W_m}{1000}
\]

---

# ۴. اضافه شدن حق ضرب یا کارمزد

سکه‌ها یا محصولات طلا معمولاً یک هزینه ثابت دارند:

- حق ضرب
- اجرت
- کارمزد پلتفرم

فرض کنیم:

\[
F = \text{MintingFee}
\]

پس قیمت نهایی:

\[
FinalPrice = BasePrice + F
\]

---

# ۵. فرمول نهایی سیستم

کل سیستم قیمت‌گذاری تو عملاً به این فرمول خلاصه می‌شود:

\[
FinalPrice =
\left(
\frac{P_{18g}}{1000}
\times
W_m
\right)
+
F
\]

که در آن:

- \(P_{18g}\) = قیمت ۱ گرم طلای ۱۸ عیار از API  
- \(W_m\) = وزن محصول بر حسب میلی  
- \(F\) = حق ضرب یا کارمزد

---

# ۶. مثال واقعی

فرض کنیم API این مقدار را داده:

\[
P_{18g} = 194{,}040{,}000 \text{ ریال}
\]

پس:

\[
P_{milli} = 194{,}040
\]

اگر محصول:

- وزن = **350 میلی**
- حق ضرب = **2,000,000 ریال**

---

ارزش طلای خام:

\[
BasePrice = 194040 \times 350
\]

\[
BasePrice = 67{,}914{,}000
\]

---

قیمت نهایی:

\[
FinalPrice = 67{,}914{,}000 + 2{,}000{,}000
\]

\[
FinalPrice = 69{,}914{,}000
\]

---

# ۷. کاری که Price Engine انجام می‌دهد

در سطح معماری سیستم، Price Engine سه مرحله دارد:

### ۱. گرفتن قیمت بازار

از API دریافت می‌کنیم:

\[
P_{18g}
\]

---

### ۲. تبدیل به قیمت واحد سیستم

محاسبه:

\[
P_{milli} = \frac{P_{18g}}{1000}
\]

---

### ۳. محاسبه قیمت محصولات

برای هر محصول:

\[
FinalPrice =
(P_{milli} \times W_m) + F
\]

---

# ۸. چرا این مدل خوب است

چند دلیل مهم:

• **ساده**  
کل سیستم به یک قیمت مرجع وابسته است.

• **هم‌راستا با بازار ایران**  
بازار طلا معمولاً با **قیمت ۱۸ عیار** کار می‌کند.

• **مقیاس‌پذیر**  
اگر فردا محصول جدید اضافه کنی، فقط وزنش مهم است.

• **آپدیت لحظه‌ای**  
با تغییر \(P_{18g}\)، همه قیمت‌ها خودکار آپدیت می‌شوند.

---

# ۹. ارتباط با UI مثل میلی‌گلد

در هدر سایت:

نمایش می‌دهی:

\[
P_{18g}
\]

و زیرش می‌نویسی:

"معادل ۱۰۰۰ میلی"

این دقیقاً همان مرجع قیمتی است که کل سیستم بر اساسش محاسبه می‌کند.

---

✅ خلاصه تصویر کلی سیستم تو:

1. API → قیمت **۱ گرم طلای ۱۸ عیار**
2. تبدیل → قیمت **هر میلی**
3. ضرب در **وزن محصول**
4. اضافه شدن **حق ضرب**
5. خروجی → **قیمت نهایی محصول**

---

اگر بخواهی، حسین، یک مرحله جلوتر هم می‌توانیم برویم و یک موضوع مهم معماری را بررسی کنیم که معمولاً در این سیستم‌ها اشتباه طراحی می‌شود:

**آیا Price Engine باید قیمت را برای هر درخواست محاسبه کند یا قیمت‌ها باید کش شوند و دوره‌ای آپدیت شوند؟**

این تصمیم روی **performance کل سیستم** خیلی تأثیر می‌گذارد.
